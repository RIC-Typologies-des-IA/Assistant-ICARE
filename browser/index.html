PRÉFÉRENCES LOCALES

Routage des moteurs d’inférence

Choisissez indépendamment où traiter l’audio et où traiter le texte. Un moteur local peut être combiné avec un Gateway distant ; les deux fonctions peuvent aussi utiliser des Gateways différents.

Choix du routage

Gateway commune

La même adresse et la même session d’authentification seront utilisées pour les deux fonctions. Les modèles sont attribués par la Gateway.

Gateway de traitement du texte

Le modèle de conversation est fourni par cette Gateway. L’authentification passe par la session de votre navigateur.

Gateway de transcription audio

Le modèle de transcription est fourni par cette Gateway. L’audio lui est transmis directement ; choisissez un moteur local si vous ne souhaitez pas envoyer votre voix à distance.

Inférence locale · Traitement du texte

API compatible OpenAI Chat Completions. localhost désigne votre propre ordinateur.

La clé est chiffrée localement avec AES-GCM et conservée dans le profil de ce navigateur.

Transcription locale · Audio

L’API doit exposer /v1/audio/transcriptions. Pour que la voix reste sur votre appareil, utilisez un serveur sur localhost ou 127.0.0.1. Un fournisseur direct distant recevra lui aussi l’enregistrement vocal.

La clé est chiffrée localement avec AES-GCM et conservée dans le profil de ce navigateur. Ce moteur est indépendant du moteur texte.

Documentation officielle Lemonade — API de transcription audio · Catalogue des modèles disponibles

Confidentialité : si la transcription est configurée sur une Gateway, l’enregistrement vocal est transmis à cette organisation. Avec une transcription locale, l’audio reste sur votre appareil et seul le texte transcrit est ensuite transmis selon le routage choisi pour le traitement du texte. Les clés locales ne sont jamais incluses dans les exports.
